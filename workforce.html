人资商结算分析

一行 = 一个结算批次（骑手 × 结算月），同一骑手有多个结算月会显示多行，结算金额只算该批次自己的金额。「结算达标天数」门槛可在工具条「结算标准」里修改；达标天数 / 达标单量 / 结算金额取线索结果明细的系统结算字段（结算金额只对归因状态「成功 / 结算完成」且金额 > 0 的骑手显示，否则显示「—」），本月班次异常数与 5 类坏单跟随账单月份。「结算预警」按风险优先级只打一个主状态：结算后≤7天离职 / 结算后离职 / 离职未结算 / 待结算达标 / 已达标未结算 / 即将达标；只有归因状态「成功 / 结算完成」且结算金额 > 0 并已离职才叫「结算后离职」，状态成功但金额为 ¥0 或仍是「待确认」的已离职骑手统一标「离职未结算」；上方预警卡片可点击筛选。
口径：人资商 = 线索结果明细 headHunterCompanyName；站点 = 归属站点（resultTeamName）；是否在职 / 入职 / 离职取成员管理·全部；首跑时间取本月出勤明细里首个「全天」完单 > 0 的日期（历史月份不在本月明细里则显示「—」）；达标天数 = effectiveRetentionDays（系统有效留存天数）；达标单量 = finishOrderNum（系统结算完单量）；结算剩余达标天数 = max(0, 结算标准 − 达标天数)，已出结算档位 / 达标天数已过门槛且账单未确认的显示「已达标」，只有结算金额 > 0 的才显示「已结算」，账单状态「成功 / 结算完成」但金额为 0 的账单已确认、直接显示「未达标」；本月班次异常数 = 出勤明细除「全天」外「是否达成=未达成」的班次数；物流责 / 投诉 / 差评 / 提前点 / 索赔 = 考核运单明细 5 类异常订单计数（索赔只算非提前点索赔）（与骑手账单、质量运营同口径）。T-3 / T-2 / T-1 单量 = 本月出勤明细里对应日期「全天」行的完单量（按「骑手id＋站点id＋日期」归集，无记录为 0 单），基准日为当月今天、历史月为该月最后一天，三列分别是基准日往前 3 / 2 / 1 个自然日；概览卡片可点击直接筛选（差 ≤5 天、离职未达标等，再点一次取消），卡片数字不受自身筛选影响。表头点 ▾ 可按该列取值多选筛选，候选值随其它筛选联动，可与搜索 / 站点 / 人资商 / 结算状态 / 只看未达标 / 概览卡片叠加；筛选只影响当前视图，导出 CSV 与复制图片按筛选后的结果出表。已结算 = 归因状态「成功 / 结算完成」且结算金额 > 0（账单已确认但金额为 0 的按不达标处理），待结算 = 归因状态「待确认」；「结算后离职」只统计真正已结算且已离职的骑手，已离职但未真正结算的统一算「离职未结算」，不混算；人资商结算分析按全量结算批次计算、不随上方表格筛选变化（人数类指标按骑手去重，结算金额 / 订单按批次累加）：已结算单均成本 = 结算金额 ÷（已结算骑手总单量 + 未结算且已离职骑手单量），待结算单均成本 =（待确认且有效留存 ≥7 天人数 × 待结算单价）÷ 待确认骑手订单量，待结算单价默认 2500 元、可在工具条修改并立即重算；结算后离职天数按结算批次时间（取不到用结算月最后一天）与离职时间计算。全部数据复用运力模块已取到的五份明细，切换子模块不产生任何额外请求。
结算达标天数标准
真机结算档位（level）从系统「有效留存天数 = 16」起出现，故默认 16 天。「结算剩余达标天数 = 标准 − 达标天数」，修改后立即重算、不重新取数。
